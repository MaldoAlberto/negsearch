# negsearch — Negation-forced amplitude amplification

Code, data and manuscript for

> **Negation-forced amplitude amplification: fewer decisions, fewer gates, and ZX-guided condition
> selection for quantum constraint satisfaction**
> Alberto Maldonado Romo, Quantum Open Source Foundation (QOSF) — alberto@qosf.net

A CNF clause is the negation of a forbidden pattern. Read as a *negative condition* it forces a
variable once all its other literals are false. `negsearch` compiles these conditions into an in-place
state preparation (each variable is its own coin) that is then amplitude-amplified, with exact success
probabilities (Lemma 3), ZX-calculus optimisation and fault-tolerant resource estimates.

## Layout
```
negsearch/core.py        problem families, negative-condition planner, exact success probability (Lemma 3)
negsearch/circuits.py    Clifford+T circuits: in-place preparation A, oracle O, reflection S0, amplification
negsearch/zxtools.py     PyZX simplification, gate accounting, equivalence checks
negsearch/heralded.py    heralded weak-measurement search for unknown success probability (Appendix A)
experiments/             one script per experiment (E0–E6) + analysis.py (figures, tables, numbers.tex)
instances/               every problem instance used, DIMACS (.cnf) with seeds and variable orders
results/                 raw results (JSON / JSONL) produced by the scripts
notebooks/               Mochila_multiple_condiciones_negadas.ipynb — hardware-ready IBM Quantum example
figures/, tables/        generated by experiments/analysis.py
main.tex, refs.bib       manuscript (compile with latexmk -pdf main.tex, or upload to Overleaf)
```

## Install
```bash
pip install -r requirements.txt
```

## Reproduce (run from the repository root)
```bash
python experiments/e1_classicality.py; python experiments/e1_classical_numpy.py; python experiments/e1_subset_original.py   # E1
python experiments/e2_driver.py a 900 '[["3-SAT",20,11]]'      # E2a: A|0> vs Lemma 3 (MPS); one run per [family, n, seed]
python experiments/e2_driver.py b 900 '[["3-SAT",12,3]]'       # E2b: full amplification (MPS)
python experiments/e3_scaling.py 3-SAT 10,15,20,25,30,35,40,45,50,55,60,70,80   # E3 (also 4-SAT, 1-in-3-SAT, 3-COL)
python experiments/e4_verify_mps.py                            # E4 equivalence of ZX-optimised components
python experiments/e45_zx.py 3-SAT 8,10                        # E4/E5 (also 1-in-3-SAT 8,10 and 3-COL 10,12)
python experiments/e6_resources.py                             # E6 fault-tolerant estimates
python experiments/export_instances.py                         # DIMACS export for E2/E4/E5
python experiments/analysis.py                                 # figures, tables, numbers.tex
latexmk -pdf main.tex
```
All random streams are seeded with fixed integers (E3 uses `zlib.crc32(family)`), so instances are
reproducible; the generated instances are also stored in `instances/`.

## Hardware example
`notebooks/Mochila_multiple_condiciones_negadas.ipynb` encodes a multiple-knapsack problem as negative
conditions, simulates it (ideal and `ibm_fez` noise model) and runs it on IBM Quantum when
`RUN_HARDWARE = True` (requires your own API key file).
